# 0. ГЛАВНАЯ ЗАДАЧА

Ты работаешь над Energy Voice Editor (EVE) — профессиональной настольной программой для создания синтетического вокала и речи.

Основная концепция проекта — создание независимой платформы, которая предоставляет пользователю возможности профессионального вокального редактора, включая редактирование нот, текста, фонем, высоты тона, выразительности, голосовых библиотек и параметров синтеза.

В качестве функциональных ориентиров рассматривай VOCALOID, Synthesizer V, OpenUtau и другие программы соответствующей категории.

Однако Energy Voice Editor должен иметь собственную архитектуру, собственные форматы данных, собственные интерфейсы и независимую реализацию алгоритмов.

Твоя задача:

1. Исследовать функциональность существующих вокальных редакторов методом Clean Room Engineering.
2. Разработать подробную техническую архитектуру Energy Voice Editor.
3. Спроектировать собственный аудиодвижок.
4. Разработать собственную систему синтеза вокала.
5. Разработать систему обычного синтеза речи.
6. Создать универсальный формат голосовых пакетов EVBANK.
7. Создать систему подключения различных синтезаторов.
8. Разработать систему Python-плагинов.
9. Обеспечить масштабируемость архитектуры.
10. Реализовывать всё постепенно, проверяя работоспособность каждого компонента.

**Главный приоритет: реальная функциональность, качество аудио, стабильность и архитектурная независимость.**

Не создавай декоративные функции, которые только имитируют работу профессионального программного обеспечения.

# 4. SINGING SYNTHESIS ENGINE

Его задача — преобразовать музыкальную информацию и текст в вокальную аудиодорожку.

## 4.1. Входные данные

Движок должен получать:

- Ноты.
- MIDI Pitch.
- Начало ноты.
- Длительность.
- Lyrics.
- Phonemes.
- Phoneme Timing.
- Pitch Curves.
- Expression Curves.
- Voicebank.
- Synthesis Backend.
- Настройки синтеза.

## 4.2. Pipeline синтеза

Разработай следующий процесс:

1. Получение данных проекта.
2. Проверка корректности данных.
3. Получение последовательности нот.
4. Получение текста.
5. Фонемизация.
6. Сопоставление фонем с нотами.
7. Получение аудиоданных или параметров модели.
8. Расчёт временных границ.
9. Расчёт высоты тона.
10. Обработка длительности.
11. Обработка переходов.
12. Применение выразительности.
13. Синтез аудиосегментов.
14. Сборка итогового аудио.
15. Передача Audio Renderer.
16. Возврат результата.

## 4.3. Concatenative Synthesis

Реализуй классический семпловый синтез на Rust.

Он должен поддерживать:

- Загрузку аудиосегментов.
- Поиск подходящих фонем.
- Выбор вариантов произношения.
- Изменение высоты тона.
- Изменение длительности.
- Соединение сегментов.
- Сглаживание переходов.
- Обработку гласных.
- Обработку согласных.
- Поддержку длительных звуков.
- Обработку коротких фонем.
- Управление атакой и окончанием звука.

Исследуй и сравни:

- PSOLA.
- WSOLA.
- Phase Vocoder.
- Crossfade.
- Pitch Synchronous Processing.
- Spectral Processing.

Не используй простое соединение WAV-файлов как полноценную реализацию синтезатора.

Выбирай подходящие алгоритмы для конкретных типов аудиоматериала.

Предусмотри возможность замены алгоритмов без изменения остального движка.

# 6. EVBANK — СОБСТВЕННЫЙ ФОРМАТ ГОЛОСОВЫХ ПАКЕТОВ

Разработай собственный формат голосовых библиотек.

Название: Energy Voice Bank.

Расширение: .evbank.

Это один из главных компонентов всей программы.

EVBANK должен быть независимым от конкретного движка синтеза.

Один пакет может поддерживать семпловый синтез, другой — нейросетевой, третий — оба варианта.

## 6.1. Общая структура

Пример:

ExampleVoice.evbank

Внутреннее содержимое:

ExampleVoice/
├── manifest.json
│
├── Audio/
│   ├── Samples/
│   ├── Phonemes/
│   └── Transitions/
│
├── Dictionaries/
│   ├── japanese.json
│   ├── english.json
│   └── russian.json
│
├── Models/
│   ├── singing.onnx
│   └── speech.onnx
│
├── Config/
│   ├── pitch.json
│   ├── expression.json
│   ├── timbre.json
│   └── synthesis.json
│

    ├── icon.png

Это логическая структура, а не обязательный набор файлов.

Отсутствующие компоненты не должны приводить к невозможности загрузить пакет, если они необязательны для выбранного движка.

## 6.3. Типы голосовых пакетов

Предусмотри:

### Sample Voicebank

Содержит аудиозаписи фонем, слогов и переходов.

Используется Concatenative Synthesis.

### Neural Voicebank

Содержит обученную модель и необходимые конфигурации.

Используется Neural Synthesis.

### Hybrid Voicebank

Содержит материалы для нескольких типов синтеза.

### Speech Voicebank

Предназначен для обычной речи.

### Singing Voicebank

Предназначен для вокального синтеза.

Пакет может иметь несколько назначений.

# 23. DEFINITION OF DONE

## EVBANK

Система считается работоспособной, когда:

- Можно создать пакет.
- Можно проверить пакет.
- Можно установить пакет.
- Можно загрузить пакет.
- Можно получить информацию о голосе.
- Можно использовать пакет в поддерживаемом синтезаторе.
- Некорректный пакет обрабатывается безопасно.

## Singing Synthesis

Система считается работоспособной, когда:

- Можно создать ноту.
- Можно ввести текст.
- Текст преобразуется в фонемы.
- Фонемы сопоставляются с аудиоданными.
- Движок генерирует аудио.
- Аудио воспроизводится.
- Аудио экспортируется.
- Изменение нот действительно меняет результат синтеза.

## Audio Engine

- Стабильное воспроизведение.
- Корректное управление аудиобуферами.
- Отсутствие критических зависаний.
- Безопасная многопоточность.
- Корректное освобождение ресурсов.

## Python Backend

- Реальное подключение к Rust Core.
- Корректная передача данных.

- Управление моделями.
- Возможность отключения backend.

- Проверка совместимости.
